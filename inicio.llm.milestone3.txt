## 3. O QUE IMPLEMENTAR AGORA (MILESTONE 3)

Seu objetivo é implementar o **Control Kernel**, que enforce limites durante a execução.

### 3.1 Budget Enforcement

Implemente em `AECS.Application` ou `AECS.ControlKernel` (se criar o projeto):

```csharp
public class BudgetEnforcer
{
    // Verifica se a execução respeitou os limites do ExecutionBudget:
    // - MaxTokens (input + output)
    // - MaxCostUsd
    // - MaxRetries
    // - MaxDurationSeconds
    // - MaxFilesChanged
    // Retorna BudgetViolation ou null se tudo ok
}
```

Requisitos:
- Verificação determinística (sem LLM)
- Retorna violação específica (qual limite foi excedido)
- Usado pelo ControlKernel antes de aceitar resultado

### 3.2 Scope Enforcement

Implemente em `AECS.Application`:

```csharp
public class ScopeEnforcer
{
    // Verifica se os arquivos modificados respeitam o ScopeDefinition
    // - Todos os arquivos devem matchear pelo menos um Allowed pattern
    // - Nenhum arquivo pode matchear um Forbidden pattern
    // Usa glob matching (ex: "src/Customers/**" matcheia "src/Customers/CustomerMapper.cs")
}
```

Requisitos:
- Glob matching determinístico (sem LLM)
- Suporta padrões como `src/Customers/**`, `tests/**/*.cs`
- Retorna lista de violações (quais arquivos violaram qual regra)

### 3.3 Circuit Breaker

Implemente em `AECS.Application`:

```csharp
public class CircuitBreaker
{
    // Monitora execução e interrompe se limites forem excedidos
    // - Verifica periodicamente (ou após cada iteração)
    // - Interrompe: budget excedido, scope violado, timeout
    // - Registra razão da interrupção
    // - Cria EvidenceEvent
}
```

Requisitos:
- Interrompe execução quando limite é atingido
- Registra razão da interrupção
- Cria EvidenceEvent do tipo apropriado
- Não depende de LLM para decidir

### 3.4 Control Kernel (orquestrador)

Implemente o orquestrador que usa os componentes acima:

```csharp
public class ControlKernel
{
    // Orquestra enforcement durante execução:
    // 1. Antes da execução: valida budget e scope
    // 2. Durante: monitora com circuit breaker
    // 3. Depois: verifica resultado contra budget e scope
    // Retorna KernelDecision (Allow, Reject, HumanReview)
}
```

### 3.5 Testes obrigatórios

Crie testes para:
- `BudgetEnforcer` — cada tipo de violação (tokens, cost, retries, duration, files)
- `ScopeEnforcer` — allowed match, forbidden violation, glob patterns
- `CircuitBreaker` — interrupção por budget, por scope, por timeout
- `ControlKernel` — integração dos enforcement components
